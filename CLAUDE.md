# Evap

App Django personnelle (usage privé, pas de compte/auth) : bloc-notes, planner (projets/tâches), calendrier, timer chrono/minuteur persistant, calculateur de moyennes. Thème rose/romantique, tout en français.

## Carte des apps

| App | Route | Rôle |
|---|---|---|
| `dashboard` | `/` | "Bureau d'élève" — 5 objets cliquables (pense-bêtes, classeur, calendrier, timer, bulletin), chacun un aperçu + raccourci vivant vers l'outil réel |
| `notes` | `/notes/` | Bloc-notes "pense-bêtes" (post-it inclinés, ruban adhésif) en grille, drag & drop pour réordonner, épinglage, couleurs |
| `planner` | `/planner/` | Projets + tâches en "classeur" (onglets projet à gauche, tâches à droite), priorités, modales de création/détail |
| `calendar_app` | `/calendar/` | Calendrier "papier" (FullCalendar sous un cadre ruban adhésif), événements récurrents (série) |
| `timer` | `/timer/` | Chrono / minuteur en "chronomètre à anneau", persiste entre les pages via un mini-widget flottant |
| `grades` | `/grades/` | "Bulletin" — tableaux de moyennes pondérées (matières/notes/coefficients), graphique doughnut |

Chaque app suit le schéma Django standard (`models.py` / `views.py` / `urls.py` / `templates/<app>/`). Pas de DRF, les endpoints AJAX sont de simples vues qui renvoient du JSON (voir chaque `views.py`).

## Passe 1 — refonte graphique initiale

**Périmètre : uniquement visuel.** Aucun modèle, aucune route, aucun contrat JSON n'a changé — seule exception ci-dessous (notes épinglées/colorées). Le but était d'élever le rendu (skill `ui-ux-pro-max`) en gardant la charte graphique existante (rose `#F472B6` / darkrose `#EC4899` / softbg `#FFF1F7`, Poppins + Merriweather) et toutes les fonctionnalités.

### Design system

- **Tokens couleur** (déclarés dans `templates/base.html`, `tailwind.config`) :
  `rose` `#F472B6`, `darkrose` `#EC4899` (actions/primaire), `softbg` `#FFF1F7` (fond), `ink` `#7A2048` (texte fort, remplace les `text-gray-500`/`text-black` incohérents d'avant), `muted` `#8A6B79` (texte secondaire), `blush` `#FBCFE8` (bordures). Sémantiques priorité/suppression restées en Tailwind standard (rouge/orange/vert).
- **Typo** : inchangée — Poppins (`font-sans`, UI/corps) + Merriweather (`font-serif`, réservée au wordmark "Evap" et aux titres `<h1>`/`<h2>`).
- **Icônes** : plus aucun emoji fonctionnel (🗑 ✔ ❌ ✕ ＋). Set SVG outline inline dans `templates/partials/icon.html` (`{% include "partials/icon.html" with name="trash" cls="w-5 h-5" %}`). Le rendu JS de `grades/grades.html` (contenu généré côté client) a ses propres constantes `ICON_*` en tête de script car les partials Django ne sont pas utilisables dans du JS.
- **Composants CSS partagés** : `static/css/evap.css` — remplace les `<style>` dupliqués (et divergents : rayons de carte 18/20/22px, tailles d'icônes 32/34px selon les pages) par un seul set : `.card`, `.btn`/`.btn-primary`/`.btn-ghost`/`.btn-danger`, `.icon-btn` (44×44 min pour la cible tactile), `.badge` (+ `-high`/`-medium`/`-low`), `.input`, `.modal-overlay`/`.modal-panel`, `.empty-state` (+ `.empty-state-icon`), `.task`, thème FullCalendar, `#evap-mini-timer`.
- **Profondeur/dynamisme** (v2 — la toute première passe était trop plate, corrigé après retour utilisateur) : tokens `--grad-primary`/`--grad-soft` (dégradés rose→darkrose) utilisés sur boutons primaires, barres `.card-accent`, header des notes, barre de progression, boutons/événements FullCalendar ; ombres teintées rose à deux couches (`--shadow-ambient`, `--shadow-glow`) au lieu de gris plat ; `.evap-bg` = deux blobs radiaux flous fixes en fond de page pour une ambiance non uniforme ; `.text-gradient` (`background-clip:text`) sur les `<h1>` de chaque page ; `.evap-sidebar` a un halo radial en haut à gauche ; stagger discret des `.fade-in` dans les grilles (`nth-child` + délai croissant) plutôt qu'une apparition simultanée. Objectif : garder la même charte, mais avec du relief — pas une nouvelle direction visuelle.
- **Layout** : `templates/base.html` est le nouveau template parent (toutes les pages font `{% extends "base.html" %}`). Sidebar devenue responsive : drawer off-canvas sous `md` avec topbar mobile + bouton hamburger (JS vanilla dans `base.html`). L'état actif du menu est calculé côté serveur (`request.path`) au lieu du JS `offsetTop` fragile d'avant.
- **Config Django** : `config/settings.py` → `TEMPLATES[0]['DIRS']` pointe maintenant vers `templates/` à la racine (nécessaire pour que `base.html` et les partials soient trouvés par toutes les apps).

### Bugs corrigés au passage (pas des nouvelles fonctionnalités)

- `static/js/evap-timer.js` déclenchait un `alert("TIMER LOADED")` à **chaque** chargement de page — supprimé.
- Il existait deux implémentations de timer en parallèle (le script inline de `timer/timer.html` et le widget global `EvapTimer`), qui pouvaient se désynchroniser. `EvapTimer` est maintenant l'unique source de vérité (state machine avec `subscribe()`) ; la page `/timer/` reflète l'état déjà en cours au lieu de toujours repartir de zéro à l'affichage.
- `planner/home.html` : le bouton ✔ (terminer) et le bouton 🗑 (censé supprimer) du projet appelaient tous les deux `close_project` — il n'existe en réalité aucune route de suppression côté backend. Le bouton trompeur a été retiré ; il ne reste qu'un bouton "Marquer comme terminé" honnête sur son action réelle. Ajouter une vraie suppression est listé plus bas.
- `planner/modals/project_modal.html` : le bouton submit utilisait `class="bg-violet ..."` — classe Tailwind invalide (pas de nuance), donc le bouton s'affichait sans fond. Remplacé par `.btn.btn-primary`.
- `grades/grades.html` lisait le token CSRF depuis le cookie `csrftoken` (`document.cookie`) au lieu de la variable de contexte `{{ csrf_token }}` comme les autres pages. Si `/grades/` était la toute première page visitée de la session, le cookie n'existait pas encore et les requêtes de création échouaient silencieusement (le bouton "+ matière" n'apparaissait jamais après "Nouveau tableau"). Corrigé en s'alignant sur le pattern des autres pages.
- La classe `.task` (lignes de tâche dans les cartes projet du planner) était utilisée dans le template mais jamais définie dans `evap.css` — les lignes s'affichaient empilées verticalement au lieu d'être en ligne (titre à gauche, badge de priorité à droite). Ajoutée.
- `templates/base.html` contenait un commentaire Django `{# ... #}` étalé sur deux lignes juste avant le `<script src="/static/js/evap-timer.js">` — **`{# #}` ne supporte pas les retours à la ligne** (contrairement à `{% comment %}...{% endcomment %}`), donc Django ne le reconnaissait pas comme commentaire et affichait le texte brut en haut de page. Repéré grâce aux captures d'écran fournies par l'utilisateur ; remplacé par `{% comment %}`.
- `notes` : les champs `Note.color` et `Note.is_pinned` existaient déjà en base (et l'endpoint `/notes/pin/<id>/` existait déjà côté vues) mais n'étaient jamais utilisés côté template — les cartes étaient toutes `bg-pink-50` et rien ne permettait d'épingler depuis l'UI. Corrigé : la couleur stockée est appliquée à la carte, un bouton épingle apparaît au survol, et les notes épinglées remontent en tête de grille.

### Non touché volontairement dans cette passe

- Aucun changement de `models.py`/`views.py`/`urls.py` en dehors de l'usage des champs notes ci-dessus.
- Aucune migration de base de données.
- Tailwind reste chargé via le CDN Play (`cdn.tailwindcss.com`), pas de pipeline de build — cohérent avec le choix existant du projet, à revoir seulement si les temps de chargement deviennent gênants.

## Passe 2 — planner en "classeur" + dynamisme (motion)

Deux demandes distinctes : (1) refonte du planner façon classeur (intercalaires = projets à gauche, page = tâches du projet sélectionné à droite) ; (2) le site jugé "trop statique" — passe d'interaction inspirée d'un catalogue de patterns motion d'un autre projet (partagé par l'utilisateur), traduit en vanilla JS/CSS (pas de framework JS ici). Principe directeur repris tel quel : *le mouvement doit être fonctionnel, jamais décoratif* — cette passe ne rajoute pas de dégradés/décor (déjà traité en passe 1), elle travaille l'interaction.

### Planner → classeur
- Première version : `.binder-tab`/`.binder-page` (bordure d'accent simple). **Remplacée dans la foulée** par une version "papeterie d'atelier" adaptée d'une maquette React fournie par l'utilisateur (`classeur-planner/`, voir `ideas.md` de ce dossier pour la direction artistique complète) : couverture + tranche à anneaux, intercalaires en trapèze (`.project-tab`, couleur hashée par projet), feuille perforée avec marge et tampon de progression rotatif. Palette ramenée à la charte rose d'Evap (la maquette source était vert forêt/laiton/ivoire) — seuls les anneaux dorés (`--classeur-ring: #C9A15B`) sont restés un accent métal, cohérent avec un thème "objet à toucher" plutôt qu'une couleur de marque.
- CSS dédié à cette seule page : `static/css/planner-binder.css` (chargé via `{% block extrahead %}`, pas dans `evap.css` partagé). Structure : `.classeur` (grid cover/spine/rail/sheet) → `.classeur-rail` (intercalaires) → `.classeur-sheet` (page active, une seule visible, bascule 100% client comme avant via `location.hash` `#p-<id>`, transition `@keyframes sheetPageIn`).
- Le tampon de progression (%) a demandé d'étendre `planner_home` : `Project.objects.annotate(total_tasks=Count(...), done_tasks=Count(..., filter=Q(task__done=True)))`, puis `percent`/`undone_tasks` calculés en Python sur le queryset évalué — nouveau, nécessaire à cet élément signature de la maquette (rien de tel n'existait avant, `tasks` ne contenait que les tâches non terminées).
- Recherche de tâches ajoutée dans chaque page (`filterTasks()`, filtrage client par titre) — nouveauté par rapport à l'ancien planner, inspirée du champ de recherche de la maquette.
- Modales (`task_modal.html`/`project_modal.html`) : classe `.paper-dialog` ajoutée (fond papier) — safe car ces partials ne sont inclus que sur cette page.
- **Bug découvert et corrigé** : `task_modal.html`/`project_modal.html` servaient déjà à la fois à créer et à consulter/modifier (`openTaskDetails`/`openProjectDetails` préremplissaient le formulaire), mais il n'existait aucune vue de mise à jour complète (seulement `update_task_date`/`update_project_date` et `close_*`). Valider le modal en mode consultation republiait donc vers `create_task`/`create_project` et **créait un doublon**. Ajouté `planner.views.update_task` / `update_project` (même style que `create_task`, formulaire standard) + routes `planner:update_task` / `planner:update_project` ; le JS du classeur bascule l'`action` du formulaire entre création et édition (`data-create-url` / `data-update-url-template` sur chaque `<form>`). `api_task` renvoie maintenant aussi `priority`/`project_id` (nécessaires pour préremplir correctement le formulaire d'édition — avant, les rouvrir et les valider aurait silencieusement remis la priorité à "Basse" et retiré le projet).

### Dynamisme site entier
- **Sidebar** (`templates/base.html`) : le fond hover/actif indépendant par item est remplacé par un unique `#sidebarHighlight` qui glisse vers l'item survolé et revient sur la page active à la sortie (pattern "un seul indicateur qui glisse", ~25 lignes JS vanilla). Fallback CSS statique conservé tant que le JS n'a pas tourné (`nav.has-js` supprime le fond statique une fois le highlight prêt).
- `@view-transition { navigation: auto; }` dans `evap.css` : fondu natif entre les pages (Evap est un site multi-pages Django classique, pas une SPA) — dégradation silencieuse sur les navigateurs qui ne le supportent pas.
- `@media (prefers-reduced-motion: reduce)` global ajouté dans `evap.css` — rien n'est piloté par un timer JS impératif dans Evap (tout passe par des classes CSS togglées), donc cette seule couche suffit à neutraliser toutes les animations/transitions.

### Non touché dans cette passe 2
- Aucune vraie suppression ajoutée (toujours "clôturer" seulement, cf. dette technique ci-dessous) — seule la modification a été comblée, pas la suppression, qui n'était pas dans la demande.
- La limitation "tâche sans projet invisible" documentée plus bas s'applique aussi au classeur : une tâche sans projet n'a toujours aucun onglet où apparaître.

## Cap donné pour les prochaines passes : métamorphose "thème scolaire"

À partir de la passe classeur, direction retenue pour le reste du site : rendre chaque page très visuelle/schématique en la faisant ressembler à l'objet scolaire réel qu'elle représente, plutôt qu'à un dashboard générique — toujours dans la charte rose Evap (les maquettes de référence, elles, ne le sont pas forcément : c'est la couleur qui s'adapte, pas la structure). Pistes données par l'utilisateur, chacune fera l'objet de sa propre passe :

- **Calendrier** → vrai calendrier (papier) (**fait passe 4**).
- **Grades** → mix calculette + bulletin de notes / tableau blanc (**fait passe 4**).

Toutes les pages ont maintenant reçu leur passe "thème scolaire" — le protocole ci-dessous reste la référence pour toute future page/fonctionnalité du même genre.

Chaque passe suit le même protocole que le classeur : lire la maquette fournie (dossier dédié avec `ideas.md` + composant React de référence), en extraire la structure/matière/interaction, adapter uniquement les couleurs à la charte Evap, implémenter en Django/Tailwind CDN/JS vanilla (pas de framework), CSS scoping par page (`static/css/<page>-*.css` chargé via `extrahead`, pas dans `evap.css` partagé) pour ne pas contaminer le reste du site tant que toutes les pages n'ont pas été reprises.

Remplace entièrement l'ancien dashboard (semaine FullCalendar intégrée + stats + priorités + liste notes) par un "bureau" de 5 objets de papeterie, adapté de `bureau-eleve/` (même protocole que le classeur : structure/matière reprises, couleurs ramenées à la charte rose — palette source bois clair/vert forêt/corail/laiton, non reprise telle quelle).

- `dashboard/views.py` réécrit entièrement (nouveau contexte : notes récentes, projet vedette avec progression, mini-grille du mois via `calendar.monthcalendar`, jours à événement, événements du jour, nombre de tâches dues aujourd'hui). Aucune nouvelle route : chaque objet consomme soit ce contexte, soit des endpoints déjà existants côté client (`/notes/api/<id>/`, `/notes/update/<id>/`, `/notes/create/`, `/grades/get_tables/`).
- Nouveau `static/css/dashboard-desk.css` (scoping par page comme `planner-binder.css`). Les tokens `--classeur-cover`/`--classeur-ring`/`--classeur-paper` ont été déplacés de `planner-binder.css` vers `evap.css` (`:root`) pour que la mini-preview classeur du bureau et la vraie page `/planner/` partagent visuellement la même "matière" sans dupliquer les valeurs.
- **Chaque objet branché sur de vraies données plutôt que reproduit à l'identique** quand la maquette ne correspond pas au modèle Evap : le bloc-notes n'a pas de case "terminé" (le modèle `Note` n'a pas ce champ) — clic ouvre une édition rapide à la place ; le timer ne simule pas un décompte, il pilote le vrai `EvapTimer` global (`EvapTimer.setMode('countdown'); EvapTimer.start(25*60)` pour "Focus 25 min" / `5*60` pour "Pause 5 min") — démarré depuis le bureau, il continue en arrière-plan et s'affiche correctement sur `/timer/` ; le bulletin n'a pas de mini-formulaire d'ajout (modèle Table→Matière→Note trop imbriqué pour un raccourci fidèle), son "+" ouvre directement `/grades/`.
- **Bug de reprise du timer découvert et corrigé** : `EvapTimer.start()` en mode `countdown` sans durée explicite (cas de la reprise après pause) ignorait `this.elapsed` (le temps *restant* sauvegardé par `pause()`) et repartait de la durée totale d'origine. Invisible avant cette passe car `timer/timer.html` repasse toujours la durée d'origine à chaque clic Start (lue depuis les champs minutes/secondes, jamais vidés) ; le bouton pause/reprise du bureau, lui, rappelle `EvapTimer.start()` sans argument et l'aurait immédiatement révélé. Corrigé dans `static/js/evap-timer.js`.
- **Bug de locale corrigé** : `config/settings.py` avait `LANGUAGE_CODE = 'en-us'` alors que tout le site est en français — invisible tant que les templates n'utilisaient que des formats de date numériques (`d/m/Y`), révélé par les nouveaux `{{ today|date:"l" }}` / `{{ today|date:"F Y" }}` du bureau (`Monday`, `August 2026`). Passé à `'fr-fr'` ; aucun autre gabarit du site n'utilise de format de date dépendant de la locale (vérifié).
- **Bug de calcul corrigé au passage** : `dashboard.views.home` construisait `notes` sans filtrer `is_deleted=False` (contrairement à `notes_home`) — une note supprimée pouvait réapparaître en aperçu sur l'accueil.
- La grille desktop fixe (3 colonnes × 3 lignes, objets de hauteur fixe façon post-it) a un piège à connaître : un objet dont le contenu peut varier (le calendrier, qui doit parfois afficher 6 semaines) doit couvrir assez de lignes de la grille, sinon son contenu déborde silencieusement avec `overflow:hidden` — le calendrier a dû passer d'1 à 2 lignes de grille pour ça (mois à 6 semaines type août 2026).

## Passe 4 — généralisation "papeterie d'atelier" aux 4 dernières pages + accueil sans chrome

Termine la métamorphose "thème scolaire" : chaque page reprend maintenant exactement le langage visuel déjà posé par sa miniature sur le bureau d'accueil, et l'accueil perd sa sidebar app (les 5 objets du bureau sont eux-mêmes la navigation). Contrainte tenue : **aucun changement de comportement** — tous les IDs/classes dont dépend le JS existant (drag & drop des notes, FullCalendar, `EvapTimer`, `calculateAll()` du calculateur) sont restés strictement identiques ; seules les classes décoratives ont changé. Chaque page garde son CSS scope-page (`static/css/notes-sticky.css`, `calendar-paper.css`, `timer-clock.css`, `grades-bulletin.css`), toutes réutilisant les tokens partagés `--classeur-cover`/`--classeur-ring`/`--classeur-paper`/`--grad-primary` d'`evap.css`.

- **Accueil sans sidebar** : `templates/base.html` encapsule desormais la topbar mobile + l'`<aside>` dans `{% block chrome %}...{% endblock %}` ; `dashboard/home.html` le redéfinit vide. Le JS du drawer/du highlight glissant avait déjà ses gardes (`if (!nav || !highlight) return;`, `openBtn?.addEventListener`), donc rien à changer côté script.
- **Notes → pense-bêtes** : cartes `.sticky-note` avec rotation légère alternée (`nth-child(3n±)`), ruban adhésif (`.washi-tape`), titre en Merriweather directement sur le papier coloré (fini la barre-titre en dégradé). Popup d'édition et modale de création passées en `.paper-dialog`.

- **Bug transversal découvert et corrigé** : `.fade-in` (utilisée depuis la passe 1 sur quasiment toutes les cartes du site) avait `animation-fill-mode: both`, qui **garde la main sur `transform` indéfiniment** après la fin de l'animation — n'importe quelle autre règle CSS ciblant `transform` sur le même élément (rotation des post-it, `:hover` qui translate/scale) était donc silencieusement ignorée depuis la passe 1. Passé à `backwards` dans `evap.css` : l'animation ne couvre plus que l'anti-flash avant démarrage, la cascade normale reprend la main une fois l'entrée terminée. Corrige au passage tous les `:hover` de type `.card:hover{transform:...}` combinés à `.fade-in` ailleurs sur le site (jamais remarqué avant, l'effet était trop proche du hover normal pour qu'un manque se voie).

## Passe 5 — raffinement agenda/timer/bulletin depuis la maquette `classeur-personnalise/classeur-planner`

Le dossier `classeur-personnalise/` (fourni par l'utilisateur) contient en réalité une seule maquette React (`classeur-planner/`), mais celle-ci couvre *deux* niveaux : `pages/Home.tsx` (le bureau d'élève, déjà utilisé passe 3) et `pages/Workspace.tsx`, qui elle-même route en interne (`wouter`, voir `App.tsx`) trois pages dédiées `/agenda`, `/timer`, `/bulletin` — jamais exploitées jusqu'ici. Cette passe reprend ces trois pages (structure + détails de matière du CSS `client/src/index.css` de la maquette) pour approfondir ce que la passe 4 avait généralisé plus sommairement, en gardant le principe habituel : adapter uniquement les couleurs (forêt/bois/laiton → rose Evap + `--classeur-ring` laiton conservé comme accent), zéro changement de comportement/contrat JS. Le bloc-notes n'est pas concerné (pas de page dédiée pour lui dans la maquette, passe 4 jugée suffisante).

- **Calendrier** (`calendar-paper.css`, `calendar_app/calendar.html`) : ajout du ruban vertical "Agenda" (pseudo-décoratif, `pointer-events:none`), d'un tampon "semaine n°" calculé en JS (`isoWeekNumber()`, ISO 8601, sur la date du jour — pas liée à la vue FullCalendar affichée), d'un pli de coin papier et d'un filet de marge, d'une petite note de bas de page (citation reprise telle quelle de `ideas.md`). Jours redessinés en Merriweather + survol teinté. FullCalendar (vues, drag&drop, récurrence, modales) strictement inchangé — uniquement du CSS + un `<div>` décoratif ajouté au template.
- **Timer** (`timer-clock.css`, `timer/timer.html`) : le cadran devient une horloge analogique décorative (chiffres 12/3/6/9, aiguilles fixes, crochet laiton en haut du cadran) — aiguilles statiques, non asservies au temps réel (aurait demandé de dupliquer la logique d'`EvapTimer` pour un effet purement cosmétique, jugé hors scope). Ajout de 3 raccourcis de durée (25/5/15 min) en mode minuteur : `startPreset(minutes)` remplit `minutesInput`/`secondsInput` puis appelle `handleStart()` existant — même pattern que les raccourcis du bureau d'accueil (`EvapTimer.start(min*60)`, passe 3), donc rien de nouveau côté `EvapTimer`. Fiche "méthode du jour" ajoutée à côté du cadran (citation statique de la maquette) ; **les statistiques chiffrées de la maquette (nb de séances, minutes cumulées) n'ont pas été reprises** — aucun modèle Evap ne trace l'historique des séances, les inventer aurait affiché des chiffres faux.
- **Bulletin** (`grades-bulletin.css`, `grades/grades.html`) : ruban "Bulletin scolaire" en haut de chaque tableau, moyenne globale transformée en tampon incliné (bordure + rotation), puce colorée par matière (cycle CSS `nth-child`, purement décoratif), barre d'impact par matière (proportion visuelle de la moyenne/20) — sa largeur est posée dans `calculateAll()` juste à côté du calcul de moyenne déjà existant (`subject.querySelector(".subject-impact-bar > span").style.width = ...`), sans toucher aux sélecteurs `.subject`/`.grade`/`.subject-average`/`.global-average`/`.chart` dont dépend le reste de la fonction. **Le modèle interactif de la maquette (tableau en lecture seule + dialogue d'ajout) n'a pas été repris** : la version Evap (édition en ligne directement dans les champs) est plus fonctionnelle et a été conservée telle quelle, seule l'habillage visuel a été enrichi.
- Deux icônes ajoutées à `templates/partials/icon.html` (`sparkles`, `trophy`) pour ces pages — même pattern que les icônes existantes (SVG outline inline, pas de nouvelle dépendance).
- **Itération corrective (1)** : un premier essai s'est contenté de décorer l'existant (ruban/tampon posés par-dessus l'ancien `<h1>` générique partagé avec le reste du site) sans reprendre la composition réelle de la maquette — jugé insuffisamment fidèle. La structure visuelle (papier, ruban, tampon, cadran analogique, ledger coloré) reste celle de la maquette — seul le texte ajouté disparaît.

## Dette technique connue (hors périmètre de cette passe)

- **Pas de suppression réelle** pour les projets/tâches du planner (seulement "clôturer" → `done=True`, qui les fait disparaître de la vue). Si une vraie suppression est voulue, ajouter des vues `delete_project`/`delete_task` + bouton dédié.
- **Pas de tests automatisés** (les `tests.py` de chaque app sont vides).
- **`requirements.txt`** est encodé en UTF-16 avec BOM (probablement collé depuis PowerShell) — `pip install -r requirements.txt` peut échouer selon l'environnement ; à ré-enregistrer en UTF-8.
- **`staticfiles/`** contient une copie figée (issue d'un `collectstatic` antérieur) de `evap-timer.js` qui a divergé du fichier source dans `static/js/`. En `DEBUG=True` avec `runserver`, Django sert directement depuis `STATICFILES_DIRS` (donc pas de souci en dev), mais penser à relancer `collectstatic` avant tout déploiement pour éviter de servir l'ancienne version en prod.
- Pas d'authentification (app à usage strictement privé/local) — à garder en tête si elle est un jour exposée publiquement.
- **Tâches sans projet invisibles** : `planner/home.html` n'affiche les tâches qu'à l'intérieur de la carte de leur projet (`{% if task.project_id == project.id %}`) — une tâche créée avec "Aucun projet" (`project` vide dans la modale) n'apparaît nulle part sur la page, alors qu'elle existe bien en base. Comportement préexistant, conservé à l'identique.
